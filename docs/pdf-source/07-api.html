01Conventions

  • All paths start with /api. Browsers call the website's own origin (https://your-domain/api/…), which forwards the request to the API.
  • Request and response bodies are JSON (Content-Type: application/json), except file upload (multipart) and QR images.
  • Every JSON response uses one envelope:
{ "success": true,  "data": { … } }
{ "success": false, "error": "Human-readable message", "details": [ { "field": "email", "message": "Invalid email" } ] }
  • Dates: request dates are YYYY-MM-DD; response timestamps are ISO 8601 in UTC. harvestDate is returned as YYYY-MM-DD.
  • Batch codes look like OT-2026-7KQ3MZ. The public trace endpoint accepts lower case.
  • Blockchain writes return a tx object: { hash, url, confirmed }. With 200/201, the transaction is confirmed and its events are already applied. With 202, it was sent but not yet confirmed; the indexer records it later.

02Authentication

POST /api/auth/login returns a JWT (HS256, 2-hour default expiry) in the body and sets it as the cookie ot_token (HTTP-only, SameSite=Lax, Secure in production). Send it either way:

Cookie: ot_token=<jwt>               # browsers (automatic)
Authorization: Bearer <jwt>          # scripts, Postman

On every protected request the API verifies the token and reloads the user. Pending or blocked accounts get 403 straight away, even with a valid token.

Access label used belowMeaning
PublicNo token
Any userAny approved, logged-in account
Role namesOnly those roles; others get 403

06Users and uploads

GET/api/users?role=processorAny user

Approved participants of one role, sorted by name, used to pick a transfer recipient. role (required): farmer, certifier, processor, distributor or retailer. 200 { users: Party[] } (no emails).

POST/api/uploadFarmer, Certifier · 30 per 15 min

multipart/form-data with one field file. PDF, PNG, JPEG or WebP detected from the content, ≤ 5 MB. The file is pinned publicly on IPFS.

{ "cid": "bafkrei…", "url": "https://gateway.pinata.cloud/ipfs/bafkrei…", "mimeType": "application/pdf", "size": 48213 }

201 · 400 missing or disallowed type · 413 too large · 502 Pinata failed · 503 uploads not configured

07Batches

All batch endpoints need a token.

POST/api/batchesFarmer
{ "product": "Basmati Rice", "quantity": 250, "unit": "kg", "origin": "Dehradun, Uttarakhand",
  "harvestDate": "2026-11-01", "certificateCid": "bafkrei…" }
product, originstring, 2–100
quantitynumber > 0, ≤ 1,000,000
unitkg | quintal | tonne | litre | dozen | piece
harvestDateYYYY-MM-DD, not in the future
certificateCidoptional, 46–100 alphanumeric characters (from /api/upload)

Registers the batch in the database and on-chain. 201 { batch, tx } · 202 { batch, tx, message } · 400 · 403 · 502

GET/api/batches?q=&status=&stage=Any user

Admins and certifiers see all batches; farmers see their own; others see batches they hold or held. Filters: q (code or product, ≤50), status, stage. 200 { batches: Batch[] }

GET/api/batches/:codeAny user

200 { batch, events: Event[], certificates: Certificate[], nextStage, canTransfer } · 404

POST/api/batches/:code/certifyCertifier
{ "approved": true, "expiry": "2027-12-31", "certificateCid": "bafkrei…(optional, replaces)" }
{ "approved": false }

Approval needs a future expiry (stored as 23:59:59 UTC on that day) and a certificate (the farmer's, or the one sent). It can be repeated until the batch is sold (renew or revoke). 200/202 · 400 · 409 still pending on-chain or already sold

POST/api/batches/:code/transferCurrent holder
{ "toUserId": "uuid of an approved user in the next role", "location": "Haridwar" }

Checks, in order: current holder and matching role (403) · registration confirmed, certified, certificate not expired, not at the retailer (409) · recipient approved and in the next role (400). 200/202 { batch, tx }

POST/api/batches/:code/soldHolding retailer
{ "location": "FC Road, Pune" }

200/202 · 403 not the holder · 409 not at retailer stage

GET/api/batches/:code/qr[?format=svg]Holding retailer, Admin

A 512 px PNG (or an SVG) QR code, error correction M, encoding {NEXT_PUBLIC_SITE_URL}/trace/{code}.

08Public trace

GET/api/trace/:codePublic · 120/min per visitor

Recomputes the trust score (including the comparison with the chain), then returns everything the QR page needs. No emails are returned.

{ "batch": Batch,
  "timeline": Event[],
  "certificates": Certificate[],
  "trust": { "score": 100, "band": "verified",
             "rules": [ { "rule": "R3", "label": "Certificate expired", "severity": "high", "impact": 25, "details": "…" } ] },
  "verification": { "badge": "verified",         // or "warning"
                    "chainChecked": true, "matchesChain": true, "differences": [],
                    "contract": { "address": "0x270C…", "url": "https://amoy.polygonscan.com/address/0x270C…" } } }

badge is verified only when the band is verified, the status is certified, the certificate hasn't expired, and the record matches the chain. 404 for unknown or malformed codes.

09Admin

All admin endpoints require the admin role.

GET/api/admin/users?status=&role=Admin

200 { users: User[] }, newest first.

PATCH/api/admin/users/:idAdmin
{ "status": "approved" }    // or "blocked"

Takes effect immediately. 400 when changing your own account · 404

GET/api/admin/fraud-alerts?resolved=&severity=Admin

Up to 200 alerts, newest first: { id, batch_code, rule, severity, details, resolved, created_at, product, trust_score }.

PATCH/api/admin/fraud-alerts/:idAdmin

Dismisses the alert (resolved = true). It reopens if the rule still triggers. 200 { alert }

GET/api/admin/analyticsAdmin
{ "users": { "byRole": {…}, "byStatus": {…} },
  "batches": { "total": 5, "byStatus": {…}, "byStage": {…}, "averageTrustScore": 80 },
  "openAlerts": { "high": 2 },
  "daily": [ { "date": "2026-11-27", "registered": 4, "certified": 4, "transferred": 7, "sold": 1 }, … 14 days ] }
GET/api/admin/gas-reportAdmin

Contents of backend/data/gas-report.json: deploy cost, per-function gas, lifecycle totals and the saving. 404 if not generated yet.
