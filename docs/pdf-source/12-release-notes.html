01Release 1.0.0: highlights

The first complete release of Organic Trace: farm-to-shelf traceability for organic produce, recorded on Polygon.

  • Full batch lifecycle: farmer registration with an IPFS certificate → certifier approval with expiry → processor → distributor → retailer → sold, every step on-chain.
  • Smart contract OrganicTrace.sol, which enforces stage order, certification and roles.
  • Shopper verification by QR code, with no app or login: journey, certificate, trust score and a live blockchain check.
  • Fraud engine with rules R1–R5, a 0–100 trust score, automatic alerts and tamper detection.
  • Dashboards for each role and an admin panel (approvals, alerts, analytics, gas analysis).
  • No crypto wallets for participants: the platform relayer signs and pays.
  • Hybrid storage that uses 53.6% less gas than storing everything on-chain.

02Changelog

[1.0.0] – 27 November 2026 (pre-release hardening)

Fixed

  • FIXPublic trace look-ups no longer share one rate limit. The trace page now passes the shopper's address to the API, so heavy QR scanning can't block other shoppers.
  • FIXHarvest dates are no longer shown one day early on servers set to IST or other time zones ahead of UTC.
  • FIXLogout clears the session cookie with the same options it was set with.
  • FIXThe database migration script works from the compiled build (Docker).
  • FIXPhone layout: the header fits on one line, batch codes no longer break across lines, and the home-page sample label no longer overflows.
  • FIXRemoved a stray build folder that caused 29 lint errors.

Changed

  • CHANGEDBatches with an expired certificate can no longer be transferred until a certifier renews them. Dashboards explain why the Transfer button is unavailable.
  • CHANGEDLogin rate limit: only failed logins count (20 per 15 minutes). Sign-ups have their own limit (10 per hour). The trace limit is raised from 60 to 120 per minute. All are now configurable.
  • CHANGEDNew visual design: paper-and-ink palette, Fraunces / IBM Plex fonts, a seal logo, a stamp-style verdict, a tick-mark trust dial, a ledger-style journey, and a redesigned home, login and sign-up.
  • CHANGED"My dashboard" link renamed to "Dashboard".

Added

  • ADDEDDocker deployment: backend/Dockerfile, frontend/Dockerfile, docker-compose.yml (website, API, indexer) and .dockerignore.
  • ADDEDProduction safety check: the API refuses to start with NODE_ENV=production and a localhost site URL.
  • ADDEDSettings: TRUST_PROXY, TRACE_RATE_LIMIT_PER_MIN, LOGIN_RATE_LIMIT, REGISTER_RATE_LIMIT; NODE_ENV and API_URL documented.
  • ADDED4 new automated tests (expired-certificate transfer, per-visitor rate limit, configuration defaults, production URL check): 83 in total.
  • ADDEDDocumentation pack (13 documents) and an OpenAPI 3.1 specification.

Security

  • SECURITYNext.js 16.4.0 → 16.4.6 (a known vulnerability in 16.4.0; the build refused to run).
  • SECURITYmulter 2.4.0 → 2.5.0, zod 4.6.5 → 4.6.7, and patched body-parser, qs and ip-address (denial-of-service fixes). npm audit: 0 vulnerabilities.

Earlier development

Development before 27 November 2026 (contract, API, indexer, fraud engine and website, built to the PRD and TRD of 9 October 2026) isn't recorded in version control: the repository had no commits at the time of this release. From now on, record every change in this changelog and in Git.

03Upgrade notes

  • New optional settings have safe defaults: TRUST_PROXY=1, TRACE_RATE_LIMIT_PER_MIN=120, LOGIN_RATE_LIMIT=20, REGISTER_RATE_LIMIT=10.
  • Production: set NODE_ENV=production and a real NEXT_PUBLIC_SITE_URL, or the API won't start.
  • Frontend build: API_URL is read at build time (the /api forwarding is compiled in) and at run time.
  • Behaviour change: users with expired batches will see the Transfer button disabled. Tell certifiers to renew.
  • No database migration needed: the schema is unchanged.
  • No contract redeployment needed: the contract is unchanged.
