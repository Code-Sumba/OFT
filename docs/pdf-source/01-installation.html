01What you are installing

Organic Trace records organic produce from the farm to the shop shelf. A shopper scans a QR code on the pack and sees the batch's full journey, its organic certificate and a trust score. Each step is also written to the Polygon blockchain, where nobody can quietly change it.

The project has four parts. On a computer, all four run at the same time:

WebsiteNext.js, port 3000. What people see in the browser.
→
APIExpress, port 4000. Logins, rules, and sending transactions.
→
DatabasePostgreSQL. Users, batches, alerts.
Smart contractSolidity, on Polygon Amoy (or a local Hardhat chain). The permanent record.
←
IndexerA background process that copies blockchain events into the database.

This guide installs everything on one computer, using a private local blockchain, so you can try the whole system without wallets, test money or online accounts. Document 2 (Setup and Deployment) explains how to connect it to the real Polygon network and put it online.

03Get the project files

Either copy the project folder you were given (for example from a ZIP file), or clone it from the repository:

git clone <repository-url> organic-trace
cd organic-trace

The folder must contain contracts/, backend/, frontend/, db/ and package.json. Every command below starts from this folder (the project root).

Secrets

Never copy a .env file from someone else's computer, and never send one by email or chat. These files hold private keys and passwords. Create your own from .env.example, as described below.

04Install the dependencies

The project has three separate Node.js packages: the smart-contract tools (project root), the API, and the website. Install all three:

# 1. Smart contract tools (Hardhat) – project root
npm install

# 2. API and indexer
npm --prefix backend install

# 3. Website
npm --prefix frontend install

This takes a few minutes the first time. When it finishes, compile the contract and run its tests:

npm run compile   # compiles OrganicTrace.sol and copies its ABI to the backend
npm test          # 25 contract tests should pass
Tip

If npm install stops with a network error, run it again; it carries on from where it stopped. On a slow connection, install one package at a time.

05Run everything locally

In local mode the blockchain is a private Hardhat network on your computer. It starts with test accounts that already hold test money, and transactions confirm instantly. You will need five terminal windows.

5.1 Start the local blockchain (terminal 1)

npm run node

Leave it running. It prints 20 test accounts with their private keys. Account #0 is used below as the relayer (the wallet the API signs transactions with). These keys are public test keys: never send real money to them.

5.2 Deploy the contract (terminal 2)

npm run deploy:localhost

This writes deployments/localhost.json, which contains the contract address and deployBlock. On a fresh Hardhat node the address is usually 0x5FbDB2315678afecb367f032d93F642f64180aa3.

5.3 Create the database

Create an empty PostgreSQL database, for example called organic:

createdb -U postgres organic

Or use pgAdmin. If you are using Supabase instead, skip this step and use its connection string.

5.4 Create backend/.env

Copy the example file, then set these values for local mode:

cp .env.example backend/.env
NODE_ENV=development
DATABASE_URL=postgresql://postgres:YOUR_DB_PASSWORD@localhost:5432/organic
RPC_URL=http://127.0.0.1:8545
# Hardhat test account #0 (public test key, local use only)
RELAYER_PRIVATE_KEY=0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80
CONTRACT_ADDRESS=<address from deployments/localhost.json>
DEPLOY_BLOCK=1
MIN_PRIORITY_FEE_GWEI=0
INDEXER_CONFIRMATIONS=0
JWT_SECRET=<at least 32 random characters>
NEXT_PUBLIC_SITE_URL=http://localhost:3000
ADMIN_EMAIL=admin@example.com
ADMIN_PASSWORD=<choose a password>
DEMO_PASSWORD=<choose a password for the demo users>
PINATA_JWT=          # leave empty: certificate uploads are switched off

To generate a JWT_SECRET:

node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"

5.5 Create the tables and the first users

cd backend
npm run db:migrate   # creates the tables from db/schema.sql
npm run db:seed      # creates the admin and one demo user per role

The seed command creates the admin account from ADMIN_EMAIL and ADMIN_PASSWORD. Because DEMO_PASSWORD is set, it also creates farmer@demo.local, certifier@demo.local, processor@demo.local, distributor@demo.local and retailer@demo.local. You can run it again safely; it skips accounts that already exist.

5.6 Start the API, the indexer and the website

# terminal 3 – API on http://localhost:4000
cd backend && npm run dev

# terminal 4 – indexer (copies blockchain events into the database)
cd backend && npm run dev:indexer

# terminal 5 – website on http://localhost:3000
cd frontend && npm run dev

Open http://localhost:3000 in a browser.

Certificate files in local mode

With PINATA_JWT empty, file uploads are switched off and the API logs "PINATA_JWT not set: file uploads are disabled". You can still register batches without a file. A certifier cannot approve a batch that has no certificate, though, so for a full local test add a Pinata key (Document 2, step 2).

06Check that it works

6.1 Automated tests

npm test                   # project root: 25 smart-contract tests
npm --prefix backend test  # 58 API tests (starts its own Hardhat node and in-memory database)

Both should finish with every test passing. The API tests take about a minute and a half.

6.2 A quick manual walk-through

  1. Log in as farmer@demo.local and register a batch, for example "Basmati Rice, 250 kg, Dehradun".
  2. Log out, log in as certifier@demo.local, click Review and approve the batch with an expiry date (this needs a certificate file; see the note in 5.6).
  3. Log in as the farmer again and Transfer → the batch to the processor. Then, as the processor, transfer it to the distributor, and as the distributor, to the retailer.
  4. As retailer@demo.local, open QR label, then Mark sold.
  5. Log out and open http://localhost:3000/trace/<batch code>. You should see ✓ Verified organic, trust score 100, and six steps in the journey.

For screenshots of each screen, see Document 3 (Website User Guide).

The local chain forgets everything when it stops

A Hardhat node keeps its data in memory. If you stop and restart it, deploy the contract again and start with an empty database (drop and recreate it, then run db:migrate and db:seed). Otherwise the database will refer to batches that no longer exist on the chain, and the trust score will flag them.

09Troubleshooting

ProblemCause and fix
Invalid environment configuration when starting the APIA required value in backend/.env is missing or wrong. The message names it, for example JWT_SECRET must be at least 32 characters or CONTRACT_ADDRESS: must be a contract address.
DATABASE_URL is not setRun the command from inside backend/, so it finds backend/.env.
ECONNREFUSED 127.0.0.1:5432 or password authentication failedPostgreSQL isn't running, or the user name or password in DATABASE_URL is wrong.
ECONNREFUSED 127.0.0.1:8545, or "Blockchain network is unavailable" in the websiteThe local Hardhat node isn't running. Start it with npm run node.
"The relayer wallet is not authorised on the contract"The contract was deployed with a different relayer. Deploy again, or make RELAYER_PRIVATE_KEY match the relayer printed by the deploy script.
EADDRINUSE (port already in use)Another copy is already running. Close it, or use another port (PORT=4001, or npm run dev -- -p 3001 for the website).
The website says "Cannot reach the server. Is the backend running?"The API on port 4000 isn't running. If it runs elsewhere, set API_URL before starting the website.
"File uploads are not configured on this server"PINATA_JWT is empty. This is expected in local mode; see Document 2, step 2.
Hardhat warns about the Node.js versionHarmless. Use Node.js 20 LTS to remove it.
A batch keeps showing "(confirming…)"The indexer isn't running. Start it with npm run dev:indexer.
Login returns "Your account is awaiting admin approval"New accounts start as pending. Log in as admin, open Users and click Approve.
