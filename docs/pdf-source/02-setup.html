01How the live system fits together

VisitorBrowser or phone
→
HTTPS proxyCoolify, nginx or Caddy
→
WebsiteNext.js :3000, the only public service
→
APIExpress :4000, private network only
SupabasePostgreSQL: users, batches, alerts
↔
API + IndexerSame code, two processes
↔
Polygon AmoySmart contract: the permanent record
↔
Pinata IPFSCertificate files
  • Participants have no crypto wallets. They log in with an email and password. The API checks what each person may do, then signs and sends the blockchain transaction with one platform wallet, called the relayer. The relayer pays all transaction fees.
  • The indexer reads contract events from the blockchain every few seconds and writes them into the database. If the network is slow, it finishes the work later and picks up where it left off after a restart.
  • The browser only talks to the website. The website forwards /api/* calls to the API, so the API never needs to be reachable from the internet.

03Step 1 – Database (Supabase)

  1. Create a project at supabase.com. Choose a region close to your users (for India: Mumbai, ap-south-1), and save the database password somewhere safe.
  2. Open Project Settings → Database → Connection string and copy the Session pooler string. It looks like this:
    postgresql://postgres.abcdefgh:PASSWORD@aws-0-ap-south-1.pooler.supabase.com:5432/postgres
  3. Put it in backend/.env as DATABASE_URL. The API connects over TLS automatically for any host other than localhost.
  4. Turn on daily backups (included in the paid plan).

04Step 2 – File storage (Pinata IPFS)

  1. Create an account at pinata.cloud.
  2. Open API Keys → New Key, give it permission to upload files, and copy the JWT. Pinata shows it only once.
  3. Set PINATA_JWT=<the JWT> in backend/.env. Leave IPFS_GATEWAY_URL=https://gateway.pinata.cloud/ipfs, or set your own dedicated Pinata gateway.

Uploaded certificates are public: anyone with the link can open them. Only the file's fingerprint (its CID) is stored on the blockchain. Accepted files: PDF, PNG, JPEG or WebP, up to 5 MB. The API checks each file's real type from its content, not from its name.

  1. In MetaMask, add the Polygon Amoy network: chain ID 80002, RPC https://polygon-amoy-bor-rpc.publicnode.com, currency POL, explorer https://amoy.polygonscan.com.

  3. Request test POL for both from the Polygon faucet (faucet.polygon.technology), choosing the Amoy network.

06Step 4 – Deploy the smart contract

Already deployed?

A contract is already live on Amoy at 0x270C6563771e17B652770211D13CCD47D7C8D41b (deploy block 49793127, relayer 0x4650…6Ae6). You can keep using it if you still control that relayer wallet. In that case skip to step 5, and see the note on DEPLOY_BLOCK there.

For a fresh deployment, fill in the root .env (used only by Hardhat):

RPC_URL=https://polygon-amoy-bor-rpc.publicnode.com
DEPLOYER_PRIVATE_KEY=0x…        # deployer wallet
RELAYER_ADDRESS=0x…             # relayer wallet ADDRESS (not its key)
CERTIFIER_ADDRESS=0x…           # optional
POLYGONSCAN_API_KEY=…           # optional, to publish the source code

Then run:

npm run compile
npm run deploy:amoy

The script deploys the contract, grants RELAYER_ROLE (and CERTIFIER_ROLE if set), saves the result in deployments/amoy.json, and publishes the source on the explorer. Write down two values from that file:

  • address → CONTRACT_ADDRESS
  • deployBlock → DEPLOY_BLOCK

If the public RPC is down, use the backup https://polygon-amoy.drpc.org as RPC_URL.

The indexer starts at DEPLOY_BLOCK. If you reuse an old contract with a fresh database, set it to the current block number (shown at the top of amoy.polygonscan.com). Otherwise the indexer first scans millions of old blocks, which takes a long time.

08Step 6 – Create the tables and the admin

cd backend
npm run db:migrate   # creates the tables (safe to run again)
npm run db:seed      # creates the admin from ADMIN_EMAIL / ADMIN_PASSWORD

If you deploy with Docker (next step), run these inside the container instead, as shown there.

09Step 7 – Put it online

Option A – Docker Compose (recommended)

The project includes docker-compose.yml, which runs three containers: web (the website), api and indexer. Only web is exposed.

# on the server, in the project folder, with backend/.env filled in
docker compose up -d --build
docker compose run --rm api node dist/scripts/migrate.js
docker compose run --rm api node dist/scripts/seed.js
docker compose ps          # all three should be "running"; api should be "healthy"

Then point your HTTPS proxy at port 3000.

  • Coolify: create a "Docker Compose" resource from the repository, add the backend/.env values as environment variables, and give the web service your domain. Coolify handles HTTPS certificates.
  • nginx or Caddy: proxy https://your-domain to http://127.0.0.1:3000 and forward the X-Forwarded-For header.

Option B – Without Docker

cd backend  && npm ci && npm run build
cd ../frontend && npm ci && API_URL=http://127.0.0.1:4000 npm run build

# keep these three running with a process manager (pm2, systemd or similar)
cd backend  && NODE_ENV=production node dist/src/server.js
cd backend  && NODE_ENV=production node dist/src/indexer.js
cd frontend && API_URL=http://127.0.0.1:4000 npm start
Do not expose port 4000

Only the website should reach the API. If port 4000 were public, visitors could forge their address and get around the rate limits. Block it in the server firewall.

11Running it day to day

Health and logs

  • GET /api/health returns ok while the API is running.
  • API logs show chain errors ("Chain error: …") and upload failures. Indexer logs show "Indexed N event(s)", or "Indexer tick failed (will retry)" when the network has a problem.
  • With Docker: docker compose logs -f api indexer.

Weekly

  • Check the relayer balance and top it up.
  • In the admin panel, review new Users and open Fraud alerts.

Changing a password

There is no "forgot password" screen yet. To set a new password for any account, create a hash on a machine that has the project, then update the database (for example in Supabase's SQL editor):

cd backend
node -e "console.log(require('bcryptjs').hashSync('NewStrongPassword', 10))"
UPDATE users SET password_hash = '<the hash>' WHERE email = 'person@example.com';

Updating the software

git pull
docker compose up -d --build
docker compose run --rm api node dist/scripts/migrate.js   # safe to run every time

12Moving to Polygon mainnet

Amoy is a test network: its POL has no value, and the network can be reset. For a commercial launch:

  1. Add a polygon network (chain ID 137) to hardhat.config.ts, next to amoy.
  2. Create new deployer and relayer wallets that have never been used on testnets, and buy real POL for them.
  3. Deploy with npx hardhat run scripts/deploy.ts --network polygon.
  4. Update RPC_URL (a paid RPC provider is recommended), CONTRACT_ADDRESS, DEPLOY_BLOCK and EXPLORER_URL=https://polygonscan.com.
  5. Start with an empty database. Amoy records cannot be moved to mainnet.
  6. Change the footer text "Testnet prototype · Polygon Amoy" on the home page.

13Troubleshooting

Message or symptomCause and fix
"Blockchain network is unavailable, please try again shortly"The RPC is down, or the relayer is out of POL. Check the balance, then try the backup RPC.
"The relayer wallet is not authorised on the contract"RELAYER_PRIVATE_KEY doesn't belong to the address that was given RELAYER_ROLE.
"Transaction sent; it will appear once the network confirms it."Normal when the network is slow. The indexer records it when it confirms, usually within a minute.
A batch stays "(confirming…)" for a long timeThe indexer isn't running, or it is still catching up from an old DEPLOY_BLOCK.
The API stops with "NEXT_PUBLIC_SITE_URL must be the public site URL in production"Set it to https://your-domain.
Logging in works, but you are logged straight out againThe site is served over plain HTTP. Production cookies need HTTPS.
"Too many requests, please slow down" for many users at onceRate limits are seeing the proxy's address. Make sure the proxy sends X-Forwarded-For and TRUST_PROXY=1.
"File uploads are not configured on this server"PINATA_JWT is empty.
"File upload to IPFS failed"The Pinata key is invalid, lacks upload permission, or the plan's limit has been reached.
tenant/user … not found when connecting to the databaseThe Supabase project was paused or deleted. Restore it, or create a new one.
The trace page says "Records do not match blockchain"The database and the chain disagree. Someone may have edited the database, or the database was restored from an old backup. Investigate before trusting that batch.
