Coding and Style Standards

The conventions the codebase already follows, written down so that new code stays consistent, plus the checks every change must pass before review.

ForAnyone changing the code
Version1.0 · 27 November 2026
Applies tocontracts, backend, frontend

01General rules

  • TypeScript everywhere, with "strict": true (root, backend and frontend). Don't use any; use unknown and narrow it.
  • Formatting: 2-space indent, double quotes, semicolons, trailing commas in multi-line lists, lines up to about 140 characters. These are followed by convention; the repository has no formatter configuration yet (see section 8).
  • Names: camelCase for variables and functions, PascalCase for types, classes and React components, UPPER_SNAKE_CASE for constants and environment variables, snake_case for database columns.
  • Files: backend modules in camelCase.ts (batchCode.ts, ethersClient.ts); React components in PascalCase.tsx; Next.js routes as lower-case folders with page.tsx.
  • Comments explain why, not what. Every exported function or class that isn't obvious gets a one-line /** … */ summary.
  • Small, focused functions. Routes stay thin and push logic into services/ and repositories/.
  • No secrets in code or Git. Configuration comes only from environment variables, declared and validated in backend/src/config.ts and listed in .env.example.
  • Dependencies: pin exact versions in package.json (as the project does) and commit the lock files. Run npm audit --omit=dev before each release.

02Solidity

  • Pin the compiler (pragma solidity ^0.8.24; Hardhat compiles with 0.8.24, optimizer 200 runs).
  • Use OpenZeppelin for access control; never roll your own role logic.
  • Custom errors (error BatchNotFound(string batchId)), not require strings. Add each new error to REVERT_MESSAGES in backend/src/chain/errors.ts.
  • Events in the past tense (BatchTransferred), carrying enough data for the indexer to rebuild state.
  • Strings as calldata in external functions; check lengths (≤ MAX_STRING_LENGTH).
  • Private state and helpers start with _ (_batches, _existing). Constants are UPPER_CASE.
  • NatSpec (@notice, @dev, @param) on every public function.
  • Order checks, then effects, then events. No external calls in this contract.
  • Any contract change: npm run compile (re-exports the ABI), add tests, run npm run test:gas, update Document 6.

03Backend (Node.js / Express)

  • ES modules with explicit .js extensions in relative imports (import { ok } from "../lib/http.js"), as module: nodenext requires.
  • Validate every input with a Zod schema via parse(schema, req.body | req.query | req.params). Never read a request field without validating it first.
  • Errors: throw the helpers in lib/http.ts (badRequest, forbidden, notFound, conflict). Express 5 forwards async errors to errorHandler. Never send raw error messages or stack traces to the client.
  • Responses: always through ok(res, data, status), which gives the { success, data } envelope.
  • Authorisation on every router: requireAuth then requireRole(...). Business checks (current holder, next role) live next to the route and are covered by tests.
  • SQL: only in repositories/ or small, clearly named queries. Always parameterised ($1); never interpolate user input. Build dynamic WHERE clauses from fixed fragments plus parameters.
  • Blockchain writes only through sendAndApply(db, trust, () => chain.method(...)), so events are applied and trust is recomputed consistently.
  • Event handling must stay idempotent: use unique keys plus ON CONFLICT DO NOTHING, and the (last_block, last_log_index) guard.
  • No emails in public responses: use loadParties / Party.
  • Dependencies are injected (createApp({ db, config, chain, ipfs })), so tests can supply an in-memory database and a fake IPFS client.
  • Logging: console.error for unexpected errors, console.warn for recoverable ones. Never log secrets, tokens or passwords.

04Frontend (Next.js / React)

  • App Router. Pages that need the session are client components wrapped in <AppShell roles={[...]}>. The public trace page is a server component that streams inside <Suspense>.
  • Call the API only through api() / useApi() in lib/api.ts (same-origin /api). Show ApiError.readable to users.
  • Shared types live in lib/types.ts and must match backend/src/services/presenter.ts.
  • Styling: Tailwind utility classes plus the design tokens in app/globals.css (bg-surface, text-muted, border-rule, text-brand…). Never hard-code colours; add a token instead. It must work in light and dark mode.
  • Reuse the components in components/ui.tsx (Button, Card, Field, Input, Notice, Pill) before creating new ones.
  • Display text: plain words, sentence case, no jargon for shoppers ("Recorded on the blockchain", not "tx mined").
  • Accessibility: labels on every input, aria-label on icon-only buttons, visible focus, native <dialog> for modals.
  • Responsive down to 360 px wide: tables turn into cards on phones (see BatchTable), with no sideways scrolling.
  • npm run lint (ESLint, Next.js core-web-vitals and TypeScript rules) must pass.

05Tests

  • Every bug fix comes with a test that fails before the fix.
  • Contract: Hardhat + Chai in test/. Test the happy path, every revert and every role.
  • API: Vitest + Supertest in backend/test/. Use setup() from helpers.ts (real local chain + pg-mem with the real schema). Test permissions (401/403), validation (400) and state conflicts (409), not just success.
  • Pure logic (fraud rules) gets plain unit tests.
  • Test names describe behaviour: "cannot transfer once the certificate has expired, until it is renewed".

06Git and commits

  • main is always deployable. Work on short branches: feature/…, fix/…, docs/….
  • Commit messages: imperative summary of 72 characters or fewer, a blank line, then why. Example: Block transfers of batches with an expired certificate.
  • One logical change per commit; don't mix formatting with behaviour changes.
  • Never commit .env, keys, node_modules, .next, dist or artifacts (all in .gitignore).

07Review checklist (before merging)

✓Check
☐npm test (root), npm --prefix backend test and npm --prefix backend run typecheck pass
☐npm --prefix frontend run lint and npm --prefix frontend run build pass
☐New input is validated with Zod; new routes have auth and role checks and tests for 401/403/400
☐No secrets, emails or private keys in code, logs or responses
☐SQL is parameterised; event handling is still idempotent
☐UI works on a phone and in dark mode; colours come from tokens
☐New environment variables are added to config.ts, .env.example and Document 2
☐Contract changes: ABI re-exported, gas report reviewed, documents updated
☐npm audit --omit=dev shows no high or critical issues
☐Changelog (Document 12) updated

08Recommended additions

These aren't in the repository yet, and are suggested to enforce the rules above automatically:

  • Prettier with { "printWidth": 140 }, applied to all three packages, to match the current style.
  • ESLint for the backend (typescript-eslint recommended rules).
  • CI (for example GitHub Actions) running the checklist commands on every pull request.
  • solhint for the Solidity code.
